EXTERNAL GUEST-ASSET PROVENANCE

Scope
-----
The assets below are fetched or supplied on demand for demos and end-to-end
tests. They are written to ignored target/test-assets/ or temporary demo work
directories; they are not tracked source, are not embedded in the host vmon
binary, and are not relicensed by the host binary's MIT license. Generated
guest initramfs/rootfs images contain their guest components and remain subject
to those components' own terms.

Fallback EDK2 nightlies (demo/run-uefi-ubuntu.sh)
- x86_64: https://retrage.github.io/edk2-nightly/bin/RELEASEX64_OVMF.fd
- aarch64: https://retrage.github.io/edk2-nightly/bin/RELEASEAARCH64_QEMU_EFI.fd
- These unofficial fallbacks are deliberately unpinned and used only when no
  explicit or distro firmware file is available. The script prints the fetched
  checksum; it does not claim verification against an upstream digest.
- Firmware terms derive from EDK2 (BSD-2-Clause-Patent) and any included module
  notices.

OCI/demo container inputs
- demo/build-oci-rootfs.sh accepts any caller-supplied OCI image and defaults to
  the mutable docker://busybox reference; its example uses docker://alpine:3.20.
- demo/guest-workloads/Dockerfile builds from the mutable alpine:3.22 tag.
- Registry manifests and package metadata at fetch time determine exact source,
  versions, and licenses. A generated filesystem must preserve the selected
  image's package notices; these inputs are not covered by the host MIT license.
